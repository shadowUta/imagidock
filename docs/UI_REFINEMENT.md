# 四主题玻璃界面与 UI UX Pro Max

本轮以用户提供的四色仪表板参考图为方向，保留暖白、石墨黑、深海蓝、冰青的柔和晕染和半透明面板。窗口与软件内弹窗采用整体圆角和内置标题栏；透明贴图直接露出预览背景。模型快照方向在 Filament 读回路径修正，不通过翻转界面截图掩盖问题。

## Skill 的实际应用范围

项目本地使用官方 `ui-ux-pro-max-cli@2.15.0` 提供的 [UI UX Pro Max Skill](https://github.com/shadowUta/imagidock/blob/main/.agents/skills/ui-ux-pro-max/SKILL.md)。原始许可证与安装来源保存在同目录；这些开发 Skill 不随便携运行时部署。应用继续使用 C++20 / Qt Widgets。

针对现有界面执行了以下检索，并核对每条结果的适用平台；命令均为 `scripts/search.py <query> --domain <domain> --json`：

| 查询 | 领域 | 采用或排除 |
|---|---|---|
| `keyboard focus modal` | ux | 采用可见焦点、对话框焦点顺序和关闭后的焦点恢复 |
| `responsive desktop overflow` | ux | 首轮偏向网页表格，改用更具体的 overflow 检索 |
| `visual hierarchy spacing` | ux | 首轮偏向移动端触控，改用 text reflow；不将移动端单位直接套入 Qt |
| `color contrast readability` | ux | 核心信息使用现有主文本色，状态同时提供文字；不生成新配色 |
| `content overflow` | ux | 采用长文本完整披露与内容可达原则，不引入 Web CSS |
| `text reflow` | ux | 采用小窗口重排原则，用 Qt 布局实现 |
| `icon button accessible label` | icons | 使用 Qt 原生可访问名称，不引入 React 图标依赖 |

## 设计约束

[配色基线](ui-tokens.baseline.json) 在 Skill 整理前记录四套颜色、语义色和原始尺寸。现有颜色保持；字体、间距和布局可以在原生桌面约束下改善。没有虚构 `--stack qt`，也没有把软件迁移为网页。

玻璃效果由缓存渐变、柔和光晕、透明面板及细描边组成。窗口使用原生窗口区域实现整体圆角，以兼容嵌入的 Filament 画面。系统文件选择器仍使用操作系统提供的对话框。

## 原生界面调整

- 正文字号为 13 px、页面标题 24 px、分区标题 12 px，间距按 4/8 px 基准整理。关键路径、来源和备份状态使用原有主文本色。
- 输入框、按钮、页签与网格有可见键盘焦点；图标按钮有原生可访问名称，资产卡片提供名称和描述。Enter 打开资产，方向键选择，Ctrl+F 聚焦搜索。
- 玻璃弹窗初始焦点落在内容区，Esc 关闭后恢复到调用控件。
- 导航、检查器和下方组织区允许纵向滚动，主预览使用固定宿主。窄窗口按当前可视高度约束主预览，适应模式保持整张图片可见；关联列表继续向下滚动。长名称和路径可换行或通过完整提示读取。

首轮小窗口检查虽然通过了无横向溢出断言，实际目检仍发现主图下部超出首屏。已修正预览区高度，并新增“图片在画布内、画布完整位于首屏”的实际几何断言；保留早期失败画面作为私有诊断记录。

随后加入了真实模型画面与帧缓冲对照。测试发现 Qt 可见状态与帧缓冲成功不能证明模型已经呈现在桌面上；原生父链、持续渲染和窗口归属均单独核对。Filament 的 WGL 交换链需要持续持有绘图上下文，原生视图现使用 `Qt::MSWindowsOwnDC`，实际桌面合成画面已确认显示正立模型。测试截图检查本进程窗口归属，锁屏或其他窗口遮挡时明确报告 `capture_blocked`；呈现比较还要求有效模型前景，避免两张空白图被误判通过。具体回归结果见验收记录。

最终回归另修复了 150% 缩放下渲染尺寸截断一像素，以及 Qt 无边框窗口从“最大化后最小化”恢复正常窗口时丢失原尺寸的问题。两档缩放各通过 52 项断言，包括自绘按钮和标题双击恢复原矩形、四种窗口状态实际呈现、键盘操作和小窗口内容可达。

可读性验证不等于 WCAG 认证：半透明表面与动态背景会影响实际对比度，装饰线、弱提示和禁用状态沿用现有色板。功能及多尺寸验证以 [验收记录](VALIDATION.md) 为准。
