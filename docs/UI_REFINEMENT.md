# 四主题玻璃界面与 UI UX Pro Max

本轮以用户提供的四色仪表板参考图为方向，保留暖白、石墨黑、深海蓝、冰青的柔和晕染和半透明面板。窗口与软件内弹窗采用整体圆角和内置标题栏；透明贴图直接露出预览背景。模型快照方向在 Filament 读回路径修正，不通过翻转界面截图掩盖问题。

## Skill 的实际应用范围

项目本地使用官方 `ui-ux-pro-max-cli@2.15.0` 提供的 [UI UX Pro Max Skill](https://github.com/shadowUta/imagidock/blob/main/.agents/skills/ui-ux-pro-max/SKILL.md)。原始许可证与安装来源保存在同目录；这些开发 Skill 不随便携运行时部署。应用继续使用 C++20 / Qt Widgets。

针对现有界面执行了以下检索，并核对每条结果的适用平台；命令均为 `scripts/search.py <query> --domain <domain> --json`：

| 查询 | 领域 | 采用或排除 |
|---|---|---|
| `keyboard focus modal` | ux | 采用可见焦点、对话框焦点顺序和关闭后的焦点恢复 |
| `responsive desktop overflow` | ux | 首轮偏向网页表格，改用更具体的 overflow 检索 |
| `visual hierarchy spacing` | ux | 首轮偏向移动端触控，改用 text reflow；不将移动端单位直接套入 Qt |
| `color contrast readability` | ux | 核心信息使用现有主文本色，状态同时提供文字；不生成新配色 |
| `content overflow` | ux | 采用长文本完整披露与内容可达原则，不引入 Web CSS |
| `text reflow` | ux | 采用小窗口重排原则，用 Qt 布局实现 |
| `icon button accessible label` | icons | 使用 Qt 原生可访问名称，不引入 React 图标依赖 |

## 设计约束

[配色基线](ui-tokens.baseline.json) 在 Skill 整理前记录四套颜色、语义色和原始尺寸。现有颜色保持；字体、间距和布局可以在原生桌面约束下改善。没有虚构 `--stack qt`，也没有把软件迁移为网页。

玻璃效果由缓存渐变、柔和光晕、透明面板及细描边组成。窗口使用原生窗口区域实现整体圆角，以兼容嵌入的 Filament 画面。应用内文件选择器使用 Qt 控件，嵌入统一的玻璃弹窗；路径验证与覆盖确认仍由 Qt 处理。

## 原生界面调整

- 正文字号为 13 px、页面标题 24 px、分区标题 12 px，间距按 4/8 px 基准整理。关键路径、来源和备份状态使用原有主文本色。
- 输入框、按钮、页签与网格有可见键盘焦点；图标按钮有原生可访问名称，资产卡片提供名称和描述。Enter 打开资产，方向键选择，Ctrl+F 聚焦搜索。
- 玻璃弹窗初始焦点落在内容区，Esc 关闭后恢复到调用控件。
- 导航、检查器和下方组织区允许纵向滚动，主预览使用固定宿主。窄窗口按当前可视高度约束主预览，适应模式保持整张图片可见；关联列表继续向下滚动。长名称和路径可换行或通过完整提示读取。

首轮小窗口检查虽然通过了无横向溢出断言，实际目检仍发现主图下部超出首屏。已修正预览区高度，并新增“图片在画布内、画布完整位于首屏”的实际几何断言；保留早期失败画面作为私有诊断记录。

随后加入了真实模型画面与帧缓冲对照。测试发现 Qt 可见状态与帧缓冲成功不能证明模型已经呈现在桌面上；原生父链、持续渲染和窗口归属均单独核对。Filament 的 WGL 交换链需要持续持有绘图上下文，原生视图现使用 `Qt::MSWindowsOwnDC`，实际桌面合成画面已确认显示正立模型。测试截图检查本进程窗口归属，锁屏或其他窗口遮挡时明确报告 `capture_blocked`；呈现比较还要求有效模型前景，避免两张空白图被误判通过。具体回归结果见验收记录。

最终回归另修复了 150% 缩放下渲染尺寸截断一像素，以及 Qt 无边框窗口从“最大化后最小化”恢复正常窗口时丢失原尺寸的问题。两档缩放各通过 52 项断言，包括自绘按钮和标题双击恢复原矩形、四种窗口状态实际呈现、键盘操作和小窗口内容可达。

可读性验证不等于 WCAG 认证：半透明表面与动态背景会影响实际对比度，装饰线、弱提示和禁用状态沿用现有色板。功能及多尺寸验证以 [验收记录](VALIDATION.md) 为准。

## 2026-10-20：Linear 面板结构参考

本轮参考 Linear 官方的 [A calmer interface for a product in motion](https://linear.app/now/behind-the-latest-design-refresh)（2026-03-12），采用紧凑页签、降低导航的视觉权重、减少重复边界及区分位置栏和视图栏的层级。四套主题继续使用 `Theme.cpp` 的原始颜色；背景渐变与柔和晕染保持，界面结构以创想坞的素材浏览和预览流程实现。

左侧以工作区导航、库内目录、素材类型和标签分组。中间内容面板上方分为两行：位置栏提供返回、主页、当前所在位置及素材添加，视图栏集中名称搜索、状态和排序。两行工具栏属于同一内容面板，下方接网格或资产详情；左右导航和信息检查器与内容面板共享上下边界，滚动发生在各自内部。

侧栏使用较弱的表面和非活动文字，主要工作区保持清晰。面板以低透明度细分隔线划分，卡片采用平整半透明表面，预览与名称／状态区之间保留一条细边界。选中和键盘焦点共用卡片外边界；悬停、选中、收藏与异常状态仍能辨认。

`UiMetrics.h` 以逻辑像素统一布局：自绘标题栏高 44 px，普通控件高 28 px，控件圆角 6 px，面板和卡片圆角 8 px，整体窗口圆角 12 px；位置栏高 44 px、视图栏高 42 px，页签底部留白 4 px。标题区与页签行空白区域继续支持系统窗口拖动，菜单、主题选择器、窗口按钮和真实页签分别保留点击、排序与拆分操作。

`UiIcons` 使用工程内自绘的线条图标，统一线宽与尺寸，绘制时从当前主题读取文字颜色，禁用态读取弱文字颜色。图标由 `QIconEngine` 按实际尺寸和缩放绘制，同一个图标对象随主题切换重新取色；按钮仍提供中文名称、提示和键盘焦点。图标不引入新的第三方图标包或独立配色。

透明图片继续按原比例完整显示，透明区域直接露出主题背景。模型缩略图与详情保持已修正的正立方向，实时 Filament 视图、关联跳转、返回历史和多窗口状态沿用原有业务层。前述 75 项检查属于上一次对齐修订的记录；本节仅描述本轮结构调整，新的构建与回归结果在取得后单独记录。


### Linear 本地修订验证范围

版本为 `0.1.0-rc.1+linear.20261020`。位置栏和视图栏改用明确的水平布局，避免嵌入式工具栏把样式边距应用到错误方向。内容面板最小宽度 440 px，最窄窗口及两侧面板拉宽时，搜索、状态和排序仍完整包含、同高且不相交。24／28 px 图标按钮分别设置实际内容尺寸，避免样式最小尺寸覆盖固定大小。右栏缩略图随实际内容区域等比缩放，重复点击当前导航仍保持选中。

本机 Release 在实际 DPR 1.0／1.5 下各通过 **89 项功能断言**，四主题的 Qt 栅格截图已目检；包括三尺寸边界和筛选极限、标题及页签输入命中、导航清栈、跨窗口同步、整图显示、图标主题像素及玻璃弹窗焦点。四个模型状态仍检查真实 Filament 帧缓冲，但**没有取得这四个状态的桌面呈现证据**。回执为 `logs/ui-ux-linear-functional-100-final2/self-test.json` 和 `logs/ui-ux-linear-functional-150-final2/self-test.json`，标有 `desktop_validation: false`，每项桌面比对明确记录 `skipped`。

`--self-test-functional` 和 `--smoke-functional` 是显式的功能检查／Qt 栅格截图模式，报告声明没有桌面呈现证据；普通启动不会截图或请求显示器唤醒，标准 `--self-test` 与便携验收仍要求真实桌面比对。当前自测截图只支持同一未旋转显示器内的完整窗口。

`0.1.0-rc.1+linear.20261020.4` 将右栏改为全宽预览与紧凑资产摘要，移除“资产信息”“名称”标题及收藏文字。预览上方和左右无内容留白，按方形区域等比完整绘图，透明处直接露出主题背景；箭头、方向键和预览内部下方圆点用于翻页。主文件独立成页，随后按已有预览顺序排列；首次可选择资产封面，普通元数据刷新保留当前页。
